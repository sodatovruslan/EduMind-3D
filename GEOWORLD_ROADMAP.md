# GeoWorld Roadmap

Статус: живой рабочий документ, обновляется по мере продвижения стадий. Не дизайн-документ (см. `EduMind_Design_System_Prep.md` для визуального редизайна — GeoWorld туда попадёт отдельной стадией, здесь — только функциональная архитектура глобуса).

## Текущее состояние (после G1)

- Глобус на сферических координатах, свой камера-контроллер (`frontend/components/geo/GlobeControls.tsx`), не Three.js `OrbitControls`.
- Текстурный шар (`EarthLayers` в `frontend/components/scenes/GeoWorldScene.tsx`) — единая NASA-style текстура на всю Землю, 4 кликабельных геологических слоя (кора/мантия/внешнее ядро/внутреннее ядро), демонстрация строения Земли в разрезе (`isCutaway`).
- Нет тайлов/LOD, нет стриминга изображений, нет границ стран/городов/лейблов, нет рельефа отдельно от базовой текстуры.

## G1 — Globe Navigation Foundation ✅ ЗАВЕРШЕНО

Унаследовано от предыдущей (не-Claude) сессии, ревью + два фикса восстановления состояния (`touchcancel`, window-level `pointerup` фолбэк). См. HANDOFF.md, продолжение №19, за полной историей.

Результат: плавный орбит, инерция, зажатые полюса, wheel-zoom, double-click-to-point, touch (drag+pinch), корректная очистка при прерванных жестах. Старый `OrbitControls` отключён, автовращение группы Земли отключено (не конфликтует с ручным управлением).

## G2 — Tile/LOD architecture spike (следующий шаг)

Цель: доказать архитектуру ДО того, как тянуть реальные тайл-провайдеры. Не про конкретный источник данных — про механизм.

- Спроектировать, как выглядит переход "низкодетальный глобус → региональные тайлы → детальные локальные тайлы" технически в Three.js/R3F: quadtree-разбиение сферы, либо простая lat/lng-сетка тайлов с несколькими уровнями зума.
- Определить, как `GlobeControls`' `dist` (расстояние камеры) мапится на LOD-уровень — уже есть готовый непрерывный параметр (`tgtDist`/`dist` в спейсе `[minDistance, maxDistance]`), новый код может подписаться на него, не трогая сам контроллер.
- Загрузка/выгрузка тайлов по видимости (frustum) + расстоянию, без блокировки основного потока.
- Промежуточный результат может быть с ЗАГЛУШЕЧНЫМИ тайлами (цветные квадраты/сетка с номерами) — цель спайка ДОКАЗАТЬ механизм LOD/loading/unloading, не подключить реальные данные ещё.

## G3 — Production imagery streaming

- Подключить реальный открытый источник тайлов (см. критерии лицензии/CORS/rate-limit/attribution ниже) поверх механизма из G2.
- Кэширование загруженных тайлов (память + опционально IndexedDB/localStorage для офлайн-переиспользования).
- Плейсхолдер/blur-up между уровнями детализации, чтобы не было резких "попапов" текстуры.

## G4 — Terrain/elevation

- Подключить открытый датасет высот (см. критерии ниже) там, где это практично.
- Смещение геометрии сетки тайла по высоте (displacement) на близких дистанциях камеры — не на уровне всей планеты сразу, ресурсоёмко.

## G5 — Countries/borders/labels

- Границы стран, названия стран/крупных городов, появляющиеся при приближении (LOD для лейблов, не только текстур).
- Вероятный источник: Natural Earth (public domain) для границ низкого/среднего разрешения, OpenStreetMap-экосистема для более детальных данных.

## G6 — Educational layer system

- Обобщить существующий паттерн 4 геологических слоёв (`EarthLayers`) в переиспользуемую систему слоёв: тектонические плиты, землетрясения, вулканы, климат, население, геология — каждый слой независимо включается/выключается, не переписывая базовый рендер глобуса.

## G7 — Geography missions/tasks

- Образовательные задания поверх системы слоёв (найти страну/объект, ответить на вопрос по слою) — переиспользовать существующий паттерн `GuidedLabPanel`/`ExperimentPanel` из Chemistry/Electricity, не изобретать заново.

## G8 — AI guide integration

- Подключить AI-учителя (по аналогии с `AITeacherChat`/`ChemistryTeacherChat`) с контекстом текущего слоя/локации камеры.

## G9 — Performance + offline/cache strategy

- Профилирование при глубоком зуме с множеством загруженных тайлов.
- Стратегия деградации на слабом железе (переиспользовать существующий `QUALITY_PRESETS` из `lib/quality-context.tsx`, не изобретать вторую систему качества).
- Офлайн-кэш для школ с нестабильным интернетом (та же мотивация, что уже задокументирована для процедурного HDRI в `CanvasShell.tsx` — не тянуть внешние ресурсы на каждую загрузку без крайней необходимости).

## G10 — Final visual/UX polish

- Согласовать с общим визуальным редизайном (`EduMind_Design_System_Prep.md`), если он к этому моменту стартует — не блокирует G2-G9, но HUD/панели поверх глобуса должны в итоге сойтись к тем же `FloatingPanel`/`TopBar` примитивам, что и остальные модули.

## Критерии выбора источника данных (обязательны для G2/G3/G4/G5 перед хардкодом провайдера)

Ничего не хардкодить, пока не проверено:
- **Лицензия** — разрешено ли продакшн/коммерческое использование (школьная платформа), не только персональное/некоммерческое.
- **CORS** — отдаёт ли провайдер тайлы с заголовками, разрешающими запрос из браузера напрямую, или нужен прокси на бэкенде.
- **Rate limits** — выдержит ли лимит нагрузку реальных школьных классов одновременно.
- **Требования атрибуции** — где и как разместить (обычно тонкая подпись поверх канваса, не блокирует §"3D space first" из дизайн-документа).
- **Не вводить платную зависимость как обязательное ядро** — Google Earth API, Cesium Ion с обязательной подпиской и т.п. исключены как core-требование по прямому указанию; open-source/open-data varianты (OpenStreetMap-экосистема, Natural Earth, открытые датасеты высот, public-domain NASA-снимки) исследуются первыми.

## Явные ограничения (не менять без отдельного решения)

- Домен-логика (`geography_engine.py` на бэкенде, событие `explore_layer`) — вне скоупа фронтенд-навигационной работы, не трогать походя при G2+.
- `GlobeControls.tsx` — камера-контроллер, не должен обрастать доменной логикой (выбор слоя, образовательный контент) — это соответствует принципу проекта "core без JSX/темы/бизнес-логики", тот же паттерн, что `ComponentDragProvider`/`WireDragProvider`.
